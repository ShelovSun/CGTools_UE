# CGToolsPublisher

`CGToolsPublisher` 是 UE 5.7 Editor 插件，用于把当前工程中已经调整完成的 UE 资产发布到 MCC 服务器，并建立与 Maya PublishTools、ShotManager 兼容的 PostgreSQL 发布记录。

## 当前版本

版本：`1.8.0`

`1.8.0` 同类型多选改为一个批量发布窗口，左侧列出全部所选资产及缩略图，点击条目查看和调整该资产。项目、类型、导出选项及【发布完成通知Maya打开】在整个批次共用，特效共用目标目录；动画的资产名、动作名和模型截图分别保留。同一源模型文件夹的 UE 包及数据库记录合并发布一次，每个所选模型仍分别输出自己的 FBX/Icon。文件夹中有同名的所选模型时直接使用其 FBX/Icon；否则由第一个所选模型补一套文件夹名的 FBX/Icon，供 AssetsManager 使用。发布前校验全部条目并拦截批次内输出重名，一次确认后执行；逐项保留成功、提示或失败原因，可以停止后续项、修改后重试。

`1.7.6` 静态网格体发布与骨骼网格体使用同样的独立 UE 字段：写入 `scene.ue_status=已完成`、`scene.ue_artist=当前发布者`。覆盖发布保留原 `scene.artist`、`scene.status`、创建日期及备注；中文名留空时保留原值。新记录的原制作为空、状态为【未开始】，UE 字段表示本次发布。需要 AssetsManagerForUE 4.3.31 及其场景数据库迁移脚本 `migrations/20261103_add_scene_ue_fields.sql`；原生迁移、FBX 关闭碰撞及其他发布流程保持原样。

`1.7.5` 静态网格体勾选【发布 FBX】时，明确关闭 FBX 导出选项【碰撞】，避免碰撞体作为额外模型出现在导出的 FBX 中。选项仅作用于本次发布任务，源网格体的碰撞和 UE 编辑器的导出设置保持原样。已经发布的旧 FBX 需要重新发布才会更新。

`1.7.4` 静态网格体改为按所属资产文件夹发布，资产名只读。例如选择 `/Game/Assets/Props/JinBiQian/JinBiQian_A1`，资产名、服务器目录、数据库名称及输出文件名都使用 `JinBiQian`；同目录的其他金币模型也归到同一个发布资产，UE 包包括整个文件夹及依赖。标准 `Assets/{类型}/{资产}`、`Scenes/{类型}/{资产}` 布局会识别所属资产根，即使模型位于 `Meshes` 子目录中也保持同一名称；其他工程内布局使用模型的直接父文件夹。静态发布继续采用 `Scenes` 和 `public.scene`，类型仍可选择或输入；骨骼发布沿用 `Assets` 和 `public.asset`。

`1.7.3` 特效发布遇到目标同名文件时，显示完整冲突列表供选择【覆盖发布】或【取消】。确认覆盖后，先将原文件备份到目标工程 `Saved/CGToolsPublisher/VFXBackups/<时间戳_GUID>/Content`，再上传并校验本次特效与依赖；未参与发布的其他文件保留。旧包中已不需要的附属文件也会先备份再移除。上传失败时尝试恢复旧文件并清理本次新增文件；确认期间目标文件有变化则取消上传，要求重新确认。取消覆盖时保留发布窗口和当前批量项。

`1.7.2` 特效发布在整理副本保存前补齐标准 `FObjectThumbnail`：优先复用原包的标准缩略图，缺失时从 Niagara/Cascade 内部预览纹理生成 256×256 图像。缩略图按发布副本名称缓存，跟随整理迁移写入最终包，供 AssetsManager 直接读取；不移动或改写源资产。没有有效预览纹理时保留原有发布行为。原生迁移回归同时验证 Niagara/Cascade 最终包的缩略图可读。

`1.7.1` 将现有的原生框选截图界面开放给 AssetsManager 使用，保留多显示器框选、移动、缩放、保存、复制、双击确定和 Esc 取消。发布面板和资产缩略图更新共用同一套截图界面。

Python 接口 `unreal.CGToolsPublisherLibrary.capture_screenshot_to_file(绝对PNG路径)` 返回 `(accepted, error)`：成功为 `(True, "")`，用户取消为 `(False, "")`，失败为 `(False, 具体原因)`。调用方提供已存在的本地临时目录；接口只写用户确认后的截图，资产最终路径的格式转换、后台保存和缩略图刷新由 AssetsManagerForUE 4.3.23 处理。

骨骼网格体的 UE 发布包包括整个资产文件夹（递归）中的资源及全部依赖，同级未被所选模型引用的其他模型也会发布。迁移后逐个验证目录内请求发布的包，缺少文件则停止上传。FBX 和 Icon 仍使用预览中的所选模型，输出文件名使用资产文件夹名；勾选 Texture 时导出整个文件夹资源引用的贴图。项目、类型、中文名默认留空、历史备份和数据库字段保护规则继续生效。

`1.6.9` 修改动画发布的资产存在性判断：所选项目的 `Assets\{类型}\{资产名}` 目录和数据库 `public.asset` 中对应的 `asset.name` 记录必须同时存在。首次发布不再要求 `Animations` 下已有该资产目录，点击确认并执行发布后会递归创建 `Animations\{类型}\{资产名}\Action`。缺少资产目录或数据库记录时提示“找不到资产”及资产名；数据库连接或查询失败时显示具体原因。上传前再次检查资产目录和记录，检查失败不写入动画输出；只查询数据库，不新建资产记录。

`1.6.8` 修复 Maya 安装在 D 盘等自定义位置时，动画发布找不到 `mayapy.exe`、无法生成 `.ma` 或打开 Maya 的问题。优先读取 ADV 的 `maya_location` 和环境变量 `MAYA_LOCATION`，再查找 Maya 2022 的 Windows 注册表安装位置（含当前用户及 32/64 位视图），最后检查本地固定磁盘的常用安装目录。反求和打开使用同一安装目录中的 `mayapy.exe`、`maya.exe`，自动查找限定为原 ADV 工具要求的 Maya 2022，不扫描整个磁盘或网络盘。找不到时列出检查过的目录、缺失程序与修正设置的位置；反求失败仍继续发布 `.uasset` 和 `.fbx`。

两种网格体的资产名均使用所属资产文件夹名且只读，UE 包递归包含该文件夹内所有资源及完整依赖；勾选 Texture 时导出整个文件夹资源引用的贴图。例如从 `JinBiQian` 中选择任意一个金币发布，资产名都是 `JinBiQian`，不会按模型名新建多个发布记录。单选的 FBX/Icon 使用文件夹名；批量发布时还为每个所选模型保留模型名的 FBX/Icon，详见下文。

Icon 默认使用 UE 的网格体资产缩略图；也可以点击“框选截图”，进入覆盖全部显示器的原屏截图模式，在任意屏幕上拖出区域作为发布 Icon。确认框选后预览会立即替换；点击“恢复缩略图”可回到自动缩略图。截图和选区只保存在内存中，不会留下临时 PNG。

支持单选或同类型多选静态网格体、骨架网格体、动画序列、Niagara 系统或 Cascade 粒子系统。单选使用原发布窗口，多选使用同一个批量发布窗口。

## 使用方法

1. 在内容浏览器中选择一个或多个同类型资产；网格体和特效需要位于当前工程 `/Game` 下。
2. 右键选择：

   ```text
   发布UE资产
   ├─ 静态网格体发布
   ├─ 骨架网格体发布
   ├─ 动画序列发布
   └─ 特效发布
   ```

3. 网格体发布：在原生发布窗口里选择项目与类型，并检查资产名、中文名、Icon、FBX 和 Texture 选项。特效发布使用下面的目录选择流程。
4. 单选点击【确定发布】并确认摘要；多选点击【批量发布】，检查目标清单后一次确认。

【发布UE资产】始终列出上述四种发布命令。单选或多选同一受支持类型时，对应命令亮起，其余命令灰显。空选择、不支持的类型或混合类型选择不能发布。Niagara 与 Cascade 是不同资产类型，分别多选发布。

批量发布使用打开右键菜单时的选中列表，左侧显示全部资产的缩略图、名称和发布结果，右侧显示当前条目的发布面板。项目和类型初始留空，只选择一次即可应用到全部条目，切换条目不会重新清空。模型的 FBX/Icon/Texture 选项、动画的 Maya 打开选项、特效的目标目录同样共用；动画的资产名和动作名可逐项修改，每个模型可以分别框选截图。同一模型文件夹对应一条数据库记录，因此中文名在这个文件夹内共用，不同文件夹各自填写。

点击【批量发布】先校验全部条目，缺少必填项、动画资产不存在或不同发布项映射到相同输出位置时，显示原因且不开始发布。校验通过后显示一次发布确认，其中说明同名内容会按各发布流程备份并覆盖。执行时逐项更新进度和结果，单项失败后继续后续项，错误原因及输出/备份路径可点击左侧条目查看。【停止后续发布】在当前项处理结束后停止；关闭或取消确认不会开始新发布。再次点击【批量发布】只处理未完成项；修改已完成条目的名称、中文名、截图或共用设置时，相应条目会重新参与发布。发布期间保持原有的窗口关闭限制，配置期间可以继续操作 UE 调整角度截图。

同一源模型文件夹的多选项只迁移一次完整 UE 包、更新一次数据库记录。勾选 FBX/Icon 时，为每个所选模型生成模型名的文件，同时保留一套文件夹名的文件。例如选择 `JinBiQian_A1`～`JinBiQian_A4`：

```text
Scenes/{类型}/JinBiQian/
├─ UE/                         # 整个 JinBiQian 文件夹及依赖，只发布一次
├─ FBX/
│  ├─ JinBiQian.fbx            # 没有所选同名模型时，使用第一个模型
│  ├─ JinBiQian_A1.fbx
│  ├─ JinBiQian_A2.fbx
│  ├─ JinBiQian_A3.fbx
│  └─ JinBiQian_A4.fbx
└─ Icon/
   ├─ JinBiQian.png
   ├─ JinBiQian_A1.png
   ├─ JinBiQian_A2.png
   ├─ JinBiQian_A3.png
   └─ JinBiQian_A4.png
```

若所选模型中已有 `JinBiQian`，直接使用它生成文件夹名的 FBX/Icon，不另加一份；否则按内容浏览器提供的选中顺序使用第一个模型。每个模型的 Icon 使用自己的截图或自动缩略图。同文件夹中未选中的旧模型 FBX/Icon 保留，覆盖前备份整个 FBX/Icon 目录，提交失败时尝试恢复。

## 动画序列发布

1. 选择一个或多个动画序列（`UAnimSequence`），右键选择【发布UE资产】>【动画序列发布】。窗口左侧展示当前动画的缩略图、原名称及包路径，便于逐项确认。
2. 弹窗包含四项：项目从 `Y:\MCCTools\config\ShotManager_config\commonSetting.json` 的 `DataBase` 数组读取，默认留空；类型为 `Characters`、`Props`，默认留空，选择项目后才能选择类型；资产名优先使用关联骨架名并去掉末尾 `_Skeleton`，例如 `BaSiTeV4_Skeleton` → `BaSiTeV4`，无法取得骨架名时才尝试关联的网格体名，可以手动修改；动作名默认使用选中的动画序列名，可以修改。
3. 点击【确定】时检查 `Y:\MCCProject\{项目}`、`Assets\{类型}\{资产名}` 目录和所选项目数据库 `public.asset` 中的 `asset.name` 记录。资产目录与数据库记录必须同时存在，否则提示“找不到资产”及资产名，并说明缺少目录或数据库记录；数据库不可访问时显示实际错误。不自动创建项目、Assets 资产目录或数据库记录。`Animations\{类型}\{资产名}\Action` 不存在时允许在确认发布后递归创建，首次发布无需手动建立动画目录。
4. 确认框显示动画名 `{资产名}_{动作名}` 和完整目标目录。点击【Yes】后生成：

   ```text
   Y:\MCCProject\{项目}\Animations\{类型}\{资产名}\Action\
   ├─ {资产名}_{动作名}.uasset
   ├─ {资产名}_{动作名}.fbx
   └─ {资产名}_{动作名}.ma
   ```

所选动画存在未保存修改时先保存该动画，再创建独立动画发布副本，以 `{资产名}_{动作名}` 同时作为包内对象名和输出文件名，通过 UE 保存为 `.uasset`。发布副本保留关联预览网格体，便于在 UE 中生成缩略图和预览动画。同时通过 UE 原生动画 FBX 导出器导出骨架动画，不包含预览网格体。源动画路径不变，骨架等外部依赖引用保留。资产名和动作名必须能组成有效的 UE 资源名。

加载旧版发布文件时，资产管理器会先备份工程内的原动画文件到 `Saved/CGTools/ActionLoading/Backups`，再修正包内对象名并重新保存；服务器文件不变。修复记录同时校验服务器源文件与本地文件的内容，重复加载不会把修复本身误判为冲突，源文件重新发布或本地动画被修改后仍会报告冲突。

动画发布始终调用共享 ADV 工具反求、烘焙并执行 QC，生成可继续编辑的 Maya ASCII 场景。原工具先将源动画和参考姿势导出到本机交接目录，再按其规则查找角色 Rig 和人工映射，使用独立 `mayapy` 生成 `.ma`。成功后校验结果属于当前动画且为 Maya ASCII 文件，复制到本地发布暂存目录并校验 SHA-256，最终以 `{资产名}_{动作名}.ma` 与 `.uasset`、`.fbx` 一起发布到同一个 `Action` 目录。Maya 场景保留原 ADV 工具生成的 Rig 和控制器动画结构，源 UE 动画位置不变。

同名文件已存在时，确认框会提示覆盖。反求成功时，三项输出一起提交；共享脚本不可读、角色检查失败、反求/烘焙失败、结果校验失败或取消时，继续发布 `.uasset` 和 `.fbx`，跳过本次 `.ma`。完成提示显示 `.ma` 失败原因、目标路径、已有报告/日志位置和保留的本地暂存目录。服务器没有旧 `.ma` 时只生成前两项；已有同名旧 `.ma` 时保留旧文件，并明确提示它未更新、不属于本次发布结果。批量窗口将该项标为【已发布，有提示】，记录详情后继续下一项。

上传前重新检查 Assets 资产目录与数据库记录，再备份本次要写入的同名文件。`.uasset`、`.fbx` 的写入错误仍会使发布失败并尝试恢复旧文件；反求成功后提交三项时，任何一项上传失败也会尝试恢复本次已写入的输出。暂存与备份在上传失败时保留，错误弹窗给出位置。该流程只查询数据库、不新增或修改记录，不迁移骨架或其他依赖。

动作名下方的【发布完成通知Maya打开】默认不勾选，**仅控制发布后是否打开 Maya**。不勾选时仍然尝试反求并发布 `.ma`，烘焙期间不打开可见 Maya 窗口。勾选且本次 `.ma` 发布成功时，启动独立 Maya 打开服务器上的新 `.ma`，不重复烘焙、不影响已打开的 Maya 场景。本次反求失败时跳过打开操作，即使服务器存在同名旧 `.ma` 也不会打开它。打开 Maya 失败时已发布的文件保留，可以手动打开 `.ma`。批量发布对每条动画独立反求，并应用共用的打开选项。

桥接脚本每次读取 `//fznas.diandian.info/AC/ADVRetargetUETool/ue57_adv_retarget_handoff.py`，沿用原工具的本机设置、交接目录、进度窗口和安全取消逻辑，不执行安装器，也不修改内容浏览器选择或工程启动脚本。生成 `.ma` 需要能访问共享工具，并满足原 ADV 工具的 Maya/mayapy、预览网格体导入路径、角色 Rig 和映射要求；这些条件不满足时仍允许发布有效的 `.uasset` 与 `.fbx`。

Maya 2022 可安装在任意盘符，正常 Autodesk 安装会从注册表自动识别。没有有效注册表记录且不在常用目录时，可在本机 ADV 设置文件 `%LOCALAPPDATA%\Autodesk\ADVRetargetTool\UE\ue57_adv_retarget_handoff_settings.json` 中设置 `maya_location`，或将环境变量 `MAYA_LOCATION` 设为实际安装根目录，例如 `D:\Program Files\Autodesk\Maya2022`（环境变量变更后重启 UE）。如配置过 `ADV_RETARGET_UE_DATA_ROOT`，ADV 设置文件以该目录为准；找不到程序时错误中会给出实际设置文件路径。插件仅在自己的共享脚本实例中替换查找函数，不修改共享工具或本机设置文件。

## 特效发布

1. 选择一个或多个 Niagara 系统（`UNiagaraSystem`），或一个或多个 Cascade 粒子系统（`UParticleSystem`），右键选择【发布UE资产】>【特效发布】。窗口左侧展示当前特效的缩略图、原名称及包路径。
2. 窗口以文件夹树展示 `Y:\MCCTools\src\UE574\VFX\Content\VFX` 的下级文件夹，隐藏 `VFX` 自身这一层，并在所有层级隐藏 `M_F`、`Mat`、`Mesh`、`Tex` 辅助文件夹。单击文件夹即可选中并展开下级，点击左侧箭头可收起分支；没有可见子目录的文件夹也可以选择。【刷新】重新读取服务器目录，并恢复已选目录所在分支。
3. 需要新目录时，选中父文件夹，点击【新建文件夹】并输入名称，创建后会自动选中新目录。未选中目录时，会在 `VFX` 下创建一级目录。重名、无效名称、网络或权限问题会显示错误。
4. 点击【确定】，确认弹窗会显示特效名称、目标工程、相对目录和完整目录，并说明副本整理和源资产保留行为。选择【是】开始，选择【否】返回目录选择窗口。

例如选择 `Y:\MCCTools\src\UE574\VFX\Content\VFX\Team1\水`：

```text
目标工程：Y:\MCCTools\src\UE574\VFX
工程内路径：/Game/VFX/Team1/水
相对目录：Content/VFX/Team1/水

Content/VFX/Team1/水/
├─ NS_Hit.uasset            # Niagara/Cascade 特效及同类型依赖
├─ M_F/                     # 材质函数及派生类
├─ Mat/                     # 材质、材质实例等
├─ Mesh/                    # 静态/骨架网格、Skeleton、PhysicsAsset
└─ Tex/                     # Texture 及派生类
```

整理使用与 `CGToolsFolderOrganizer` 相同的真实资产类型规则。范围是选中特效及递归引用到的 `/Game` 包依赖（硬引用和软引用），不会扫描并发布源文件夹中无关的兄弟资产。其他类型依赖（例如 Niagara 发射器、参数集合和数据接口资产）保持原包路径并一并迁移，因此目标 Content 下也可能出现这些依赖原有的目录。`M_F`、`Mat`、`Mesh`、`Tex` 四个目录始终建立。

流程是**先创建并整理独立副本，再迁移到服务器**：确认后 UE 会保存当前工程未保存的内容，递归收集特效依赖，将源包实例化到 `Saved/CGToolsPublisher/VFX/<GUID>/Copies/Content` 的独立临时挂载点，按目标目录整理副本，并在加载副本时映射包名和软引用。随后通过 UE 原生迁移将副本写入 `Saved/CGToolsPublisher/VFX/<GUID>/Content`，转换为目标工程的 `/Game/...` 引用。校验所有计划包后由后台线程检查目标文件；存在同名文件时，在可滚动的列表中列出本次将替换的特效、材质、贴图等文件，用户选择【覆盖发布】后才上传，没有冲突时直接上传。完成后卸载副本、清理暂存目录并定位到原特效。源特效及依赖保留在原位置，当前工程的引用关系保持不变；当前工程中已存在的 `/Game/VFX/...` 内容也不会被覆盖。

多个源包被整理到同一目标包时仍会报错，因为无法确定应保留哪一个源资产。目标服务器已有同名文件则可由用户确认覆盖，点击【取消】或关闭确认框时不写入服务器文件，并停留在当前发布面板。覆盖确认包括本次包的旧 `.uexp`、`.ubulk`、`.uptnl` 等附属文件；新包不再需要的旧附属文件会备份后移除，其他资产保留。

上传在后台线程进行，先校验全部临时上传文件、备份并验证原文件，再提交替换。原文件备份保留在目标工程 `Saved/CGToolsPublisher/VFXBackups/<时间戳_GUID>/Content/<原相对路径>`，并附带 `manifest.txt` 清单；发布完成弹窗显示备份位置。提交失败会尝试恢复本次替换的文件并清理本次新增文件，无法自动恢复时显示具体路径与备份位置。使用工程级文件句柄锁避免本版本发布器并发写入；确认后会重新校验目标内容，变化时取消上传并要求重试。副本整理、保存或迁移失败时会报告具体阶段，源资产位置保持不变；确认后的源工程内容保存操作可能已经完成。

引擎内容及插件内容保留原挂载路径引用，目标工程需要相同引擎版本和对应插件。本流程不写 ShotManager 数据库，不导出 FBX、Icon 或 Texture 源文件；它直接向现有 VFX 工程发布 UE 包文件。不能从 VFX 目标工程自身向自身发布。Y: 目录不可访问时窗口显示原因，【确定】不可点击，可以在恢复网络盘后刷新。

【发布UE资产】菜单使用插件自带的 `Resources/pub_upload.png` 图标，以 16×16 Slate 单位显示。图标随插件分发，安装后从插件自身目录读取。

CGTools 使用独立的 ToolMenus 菜单分组，位于原生资产操作之后。MetaHuman DNA 等其他插件的资产菜单不会显示在 CGTools 标题下。

插件从以下唯一配置读取项目列表、根路径与数据库地址：

```text
Y:\MCCTools\config\ShotManager_config\commonSetting.json
```

这里是 `ShotManager_config`，不是 `ShotManager\_config`。

数据库地址必须在这份 JSON 中配置为非空字符串，例如 `"host": "smnas.diandian.info"`；端口保持 `5432`。资产管理器各页、原生后端与发布插件都使用此字段，不再回退到写死的 IP。发布窗口读取它来检查配置，Python 数据库接口在每次连接前重读它，避免窗口已打开时仍保留旧地址。`host` 缺失、为空或配置不可读时会显示错误。

## 发布目录

静态网格体发布到：

```text
{rootPath}/{project}/Scenes/{类型}/{资产名}/
├─ UE/
│  ├─ Content/                 # 所选 .uasset 及 UE 原生迁移解析出的完整包依赖
│  └─ {资产名}.uproject
├─ FBX/
│  └─ {资产名}.fbx            # 【发布 FBX】默认勾选
├─ Texture/                    # 【发布 Texture】勾选后导出依赖贴图源文件
└─ Icon/
   └─ {资产名}.png            # UE 静态网格体原生缩略图
```

例如：

```text
Y:\MCCProject\GOF\Scenes\StaticMesh\QiDian\UE\Content
Y:\MCCProject\GOF\Scenes\StaticMesh\QiDian\UE\QiDian.uproject
```

`UE/Content` 使用 `IAssetTools::MigratePackages` 发布，包含整个资产文件夹（递归）的资源及它们引用的材质、材质实例、贴图等包依赖，包括未被所选模型引用的同级模型，并保持它们在 `/Game` 下的相对包路径。迁移后逐个验证目录资源包，缺少包时停止上传。

骨架网格体发布目录为：

```text
{rootPath}/{project}/Assets/Characters/{资产名}/
{rootPath}/{project}/Assets/Props/{资产名}/
```

骨架网格体使用与静态网格体相同的 UE 原生依赖迁移、Icon、FBX 和可选 Texture 流程，但数据库记录写入 `public.asset`，使发布结果能被 AssetManager 的资产页读取。

## 数据库规则

数据库名使用 UI 中选择的项目名。静态网格体记录写入：

```sql
public.scene
```

骨架网格体记录写入：

```sql
public.asset
```

新记录使用 Maya Scene 发布器一致的字段：

```text
scene.date
scene.name
scene.zh_name
scene.artist
scene.status
scene.icon
scene.type
scene.note
scene.ue_status
scene.ue_artist
```

骨架网格体使用 Maya 资产发布器一致的 `asset.*` 字段，包括 `asset.name`、`asset.zh_name`、`asset.mod_artist`、`asset.mod_status`、`asset.icon`、`asset.type` 和 `asset.note`。

- 没有同名记录时建立新记录，创建日期为当天；中文名未填写时保存为空。两种网格体的 UE 状态为【已完成】、UE 制作为当前发布者，原制作为空、原状态为【未开始】。
- 已有同名记录时会明确提醒是否覆盖。
- 覆盖时保留原创建日期（`scene.date` / `asset.date`）；中文名（`scene.zh_name` / `asset.zh_name`）留空或只有空白时保留原值，填写非空内容时才更新。
- 覆盖骨骼资产时更新 `asset.ue_artist`、`asset.ue_status`（【已完成】）、Icon 和类型，保留模型制作、模型状态、绑定信息与备注；静态场景更新 `scene.ue_artist`、`scene.ue_status`（【已完成】）、Icon 和类型，保留原制作人、状态及备注。
- 数据库写入发生在服务器文件发布并验证成功之后，避免产生“数据库有记录、发布文件却不存在”的记录。

数据库登录信息不会写入插件、日志、`.uproject` 或发布目录。插件和 Maya 发布器一样读取：

```text
%APPDATA%\ShotManagerTemp\setting.json
```

若该文件不存在，则读取：

```text
%APPDATA%\ShotManagerTemp\Configs\prefs.ini
```

插件携带与 UE 5.7 Python 3.11 匹配的 `psycopg2-binary 2.9.12`，仅用作现有 PostgreSQL 数据库适配层。第三方许可见 `ThirdPartyNotices/psycopg2-LICENSE.txt`。

## 覆盖与恢复

发布先在资产目录内的唯一暂存目录中完成 FBX、Icon、可选 Texture、`.uproject` 和 UE 依赖迁移。主 `.uasset` 验证通过后才提交到正式目录。

若正式目录已有文件，插件会先备份到：

```text
{资产目录}/history/{时间}_{短GUID}/
```

提交失败时会尝试自动恢复原版本。发布成功弹窗会显示本次旧版本备份路径。

## 限制

- 接受一个或多个同类型的 `UStaticMesh`、`USkeletalMesh`、`UAnimSequence`、`UNiagaraSystem` 或 `UParticleSystem`，混合类型选择时禁用发布命令。
- 源网格体或特效必须位于当前项目 `/Game` 下。
- 发布电脑必须能访问 `Y:` 服务器映射；网格体发布还需要 PostgreSQL `5432` 端口和 ShotManager 登录配置。
- 本插件是 Editor 工具，不参与游戏运行时打包。
