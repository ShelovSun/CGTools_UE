# AssetsManagerForUE

## 默认不勾选与部分加载状态修复（4.3.28）

加载冲突窗口的缺失文件与已有冲突文件一样默认不勾选，由用户选择加载内容。只加载部分文件后，刷新 UE 注册表不再因为主资产可用就把整个发布包标为绿色：仍有内容不同的文件时显示黄色冲突状态；仍有缺失文件时显示黄色不完整状态；资产主体尚未加载时保留未加载状态。只有文件齐全、内容一致且 UE 注册/重新加载成功后才可能显示绿色。复制完成的内容校验在后台线程执行，支持识别大小相同但内容不同的保留文件，界面刷新直接使用检查结果。

## 缺失文件也通过勾选加载（4.3.27）

加载冲突窗口的缺失文件首列改为与其他文件相同的勾选框，不再显示【新增】文字；保留红色图标和工程大小列的【缺失】提示。缺失项默认勾选，取消勾选后本次跳过，【全选】【反选】和表头勾选同时操作冲突项及缺失项。点击【全部保留并加载】保留所有已有冲突文件，并仅补齐当前勾选的缺失文件。未加载的文件仍按实际缺失状态参与后续检查。

## 加载冲突窗口展示新增文件（4.3.26）

【加载资产冲突】窗口同时列出服务器已有、当前工程缺失的新增文件。新增项放在列表前方，使用红色图标，首列标记【新增】，工程大小列标记【缺失】；顶部说明和底部统计也显示新增数量。新增文件仍随加载自动补齐，【全选】【反选】和表头勾选仅操作需要决定覆盖或保留的冲突项，新增项不会进入覆盖/保留清单。点击【全部保留并加载】保留现有文件并加载所有新增文件，点击【取消】不执行复制。此窗口由资产、场景、蓝图、特效及组件加载共用，均采用相同展示规则。仅有缺失文件、没有冲突时沿用直接加载流程。

## 添加与删除资产/场景（4.3.25）

【资产】和【场景】页工具栏新增【＋】按钮，对应 Maya 的 Add Asset / Add Scene。弹窗可选择项目、类型，填写资产名和中文名，默认选中当前项目/类型；项目来自共用 commonSetting.json 的 DataBase，类型随项目读取服务器目录（资产目录为空时使用配置的 type）。确定后使用当前登录账号写入相应 asset / scene 表，日期为创建当天，初始状态为【未开始】；已有同项目、类型、名称记录时提示重复，不覆盖数据。资产同时创建 Design/FBX/Icon/Image/Mod/Original/Rig/Texture 以及同项目 Animations/<类型>/<资产名>/Action；场景创建 Assembly/FBX/GPU/Icon/Mod/Original/Port/Proxy/Texture。icon 字段指向 Icon/<资产名>.png，未截图时沿用默认缩略图。添加窗口非模态，数据库和文件操作在后台完成，成功后更新对应列表并保留筛选和排序。

卡片右键新增【删除...】，与 Maya 一致分两次确认：先删除当前项目、类型、名称及 icon 匹配的数据库记录；成功后移除卡片，再询问是否永久删除服务器资产文件夹。两次确认都默认【否】。选择保留文件夹时只删除数据库记录。文件删除严格验证 rootPath/项目/Assets（或 Scenes）/类型/资产名与原 icon 路径一致，拒绝越级路径、链接或重定向目录；路径异常时只报告文件未删除。数据库删除失败不会继续删除文件。服务器文件删除失败会明确报告数据表已删除及失败目录、原因。删除不涉及当前 UE 工程 Content 中已加载的副本，也不删除独立的 Animations 动作库。

## 搜索开销与卡顿诊断（4.3.24）

搜索先对内存中的资产名、中文名匹配，再为结果创建卡片及缩略图 worker；不再为所有未匹配记录构建 Qt 对象。英文资产名仍忽略大小写，中文名保留原匹配规则，回车搜索不重新查询数据库。清空列表时停止当前悬停动画并清除旧卡片引用。普通 PNG/JPG 等静态图悬停不再同步访问服务器判断 GIF 或序列目录，GIF 和 thumbnail.jpg 对应的 sequence 目录保持原有功能。

资产页每次回车搜索会在本地 `%LOCALAPPDATA%/CGTools/AssetsManagerForUE/diagnostics/search-<进程号>.log` 记录搜索词、资产数量，以及清空列表/预览、排序、构建卡片、布局、安排后台检查的分段耗时。搜索超过 5 秒，自动保存全部 Python 线程堆栈；记录在本地刷新写入，强制关闭 UE 后仍可查看。诊断覆盖搜索同步调用及紧接着的界面事件，事件循环恢复后取消超时计时，不常驻扫描。单个日志超过 5 MiB 时保留一个旧文件后继续记录。UE Output Log 会打印当次日志路径。

这次未能取得用户之前强制结束 UE 时的卡死堆栈，因此上述修改针对已确认的多余对象创建和界面线程文件检查，不能据此认定已找出偶发持续卡死的唯一原因。诊断文件用于下一次区分具体阻塞阶段和 Python/UE 原生调用。

## 右键更新缩略图（4.3.23）

【资产】和【场景】页的卡片右键菜单新增【更新缩略图】。点击后暂时隐藏 AssetsManager，打开 CGToolsPublisher 的原生框选截图界面；点击【确定】或双击选框内部，替换数据库 icon 路径指向的图片并立即刷新对应卡片及当前图片预览。按 Esc 或【取消】保留原图并恢复窗口。

无需先加载 UE 资产，也不受加载冲突或 UE 状态限制；已有 icon 路径但图片缺失时同样可截图。保存保持原路径和 PNG/JPEG 等原图片格式，不修改数据库字段。允许补建资产目录下缺失的 Icon 子目录；资产目录不存在、路径为空、格式不支持、无写入权限等情况会提示原因。

网络文件写入在后台执行，使用同目录临时文件完成替换，失败时保留原图。保存后直接更新卡片图片缓存，不重建列表或触发整页检查，保留筛选、选中项与滚动位置；同时忽略尚未完成的旧缩略图解码结果，避免新图被覆盖。截图需要 **CGToolsPublisher 1.7.1 或更新版本**，更新插件 DLL 后需重新启动 UE。

## UE 制作中也可加载（4.3.22）

资产页数据库 `asset.ue_status` 为【制作中】或【已完成】时，都进入后台加载检查；顶部【加载资产】和右键同名菜单使用相同条件，未开始、空值等状态继续跳过。右上角 UE 角标仍只在【已完成】时显示，加载资格与完成标记独立。

两种可加载状态都先检查当前工程的资产文件夹；目录不存在时立即结束自动检查并允许点击加载，实际点击后重新验证服务器发布包。目录存在时仍检查发布文件是否可用及同步冲突；服务器没有完整主包时禁用加载，显式加载仍保留原有依赖校验和冲突选择。

## 先检查本地资产目录（4.3.21）

自动检查按以下顺序执行：资产页先读取数据库 `asset.ue_status`（4.3.22 起【制作中】和【已完成】均进入后台检查）；场景页保持使用 `scene.status == UE`。然后根据卡片资产根目录检查当前工程 `Content/Assets/{类型}/{资产名}` 或 `Content/Scenes/{类型}/{资产名}` 是否存在。目录不存在时立即显示未加载，不读取服务器目录、清单、文件名或文件大小；加载按钮依照数据库可加载状态可用，实际点击后重新验证服务器包。

本地目录存在才进入服务器发布包发现、主体确认和依赖比较。比较大小前先判断本地对应文件是否存在，缺失文件不读取服务器文件大小。目录存在不直接认定为完整加载。点击【加载资产】仍建立完整迁移计划并校验内容、处理全部依赖冲突，自动检查的简化结果不能用来复制文件。

CGToolsPublisher 1.7.0 骨骼网格体以资产文件夹名发布，并递归发布该文件夹及依赖，使数据库资产名与 UE 目录一致。历史使用模型名且与目录不同的卡片，自动检查按数据库目录快速判断，定位和实际加载仍保留历史包路径兼容；不自动改写旧数据库记录。

## 自动检查提前结束（4.3.20）

资产页首先读取数据库 `asset.ue_status`；4.3.20 当时只允许【已完成】，4.3.22 起扩展为【制作中】或【已完成】，不再借用右上角 UE 角标作加载门槛。其他状态立即结束检查，不访问服务器或工程文件。场景页按现有 `scene.status == UE` 标记执行同样规则。编辑发布状态后会重新安排检查。

已发布资产优先读取发布清单声明的主包，工程中没有主包就显示红色并跳过依赖检查。没有主包清单的旧发布包先遍历文件名、相对路径，按原有主体识别规则处理同名包、历史文件夹名和多主体包；主体缺失时不读取依赖大小。此类旧包仍需目录遍历，不能省去该部分网络 I/O。主体存在时，仅对服务器和工程中都存在的文件读取大小并判断差异，工程缺失文件直接记为缺失。

以上提前结束仅用于自动检查。点击【加载】仍重建完整计划、核验所有依赖及内容哈希、选择同名冲突文件，随后执行复制和自动重载；未加载主体不能掩盖共享材质等文件的覆盖冲突。

## 覆盖后自动重载（4.3.19）

已加载的资产包在磁盘替换后通过 UE 原生 API 重新加载，然后才刷新注册表和状态。覆盖前确认放弃目标资产的未保存修改；重载失败会显示待处理状态并支持重试，后台扫描不会直接变绿。

## 主资产与共享依赖（4.3.18）

资产页、场景页的【在内容浏览器中定位】和关卡拖放只选择该卡片自己的资源。发布包里的共享材质、贴图和其他资产依赖不再代替当前资产；例如只有 `Assets/MasterMaterial/blue.uasset` 时，不会把未加载的模型定位到这张贴图。

主体包不存在时，卡片显示未加载，共享依赖已存在或有冲突不会把卡片变为黄色。加载操作仍检查全部依赖，并对冲突弹窗供用户选择覆盖或保留。主体存在且与服务器不一致时仍显示黄色，本地旧版本仍可定位和拖放。

识别优先使用发布清单主包、资产同名包（兼容 `SM_`、`SK_`、`BP_` 前缀）及约定资产目录。历史发布包的文件夹与资产名称不同，如 `LanWangD/LanWangD2.uasset`，也能按同名包识别。材质、骨架、地图等本资产目录内的资源仍可定位。自动检查仍只调用文件系统，不加载 UE 对象；蓝图分类、特效和组件库保持各自的加载范围。

## UE 原生启动提示（4.3.17）

【CGTools → AssetsManager】先通过轻量 `launcher.py` 打开 UE 原生进度窗口，显示【正在启动...】；菜单返回后等待两次 Slate post-tick，再导入 PySide6 和主窗口。首次页面构建完成后自动关闭提示；导入失败、窗口销毁时也会清理提示与回调，启动期间重复点击不会重复打开窗口。

启动脚本与 EUW 的打开入口使用同一流程。输出日志会记录启动界面准备耗时。此提示用于观察首次导入、窗口构建期间的等待，不代表首次卡顿原因已确定或耗时已消除。

已运行的 UE 会保留旧菜单命令，重启后菜单入口生效；也可将输出日志的命令类型切换为 Python，运行 `from AssetsManagerForUE import launcher; launcher.showWindow()` 立即体验启动提示。

## 检查线程与界面响应（4.3.16）

资产页、场景页的自动状态检查只比较发布包与工程文件，不再为卡片颜色加载或解析蓝图。主资产解析留到实际拖放、定位或加载时执行；自动检查显示的绿色表示发布文件已在工程中且大小一致，能否放入关卡仍在拖放时单独判断。

点击和滚动只查询当前选中项及可视网格，保留其余待检查队列；缩略图也只更新进入、离开可视区和预取带的卡片。场景检查结果直接通过卡片映射更新，避免每个结果从头查找整张列表。原有“点击项 → 可视区域 → 其余筛选结果”的顺序保持不变。

后台检查限制最多 8 条未处理的界面回调，并在检查之间短暂让出执行时间。刷新、关闭时可在目录、文件及校验块之间取消；已经进入系统的单次网络 I/O 仍需等待系统返回，但关闭资产管理器不会在 UE 主线程等待它结束。

资产页、场景页点击【加载资产】后的源目录遍历和 SHA-1 内容校验也改为后台任务，检查期间禁用重复加载。检查结束后，在主线程显示原有冲突选择并执行 UE 注册操作。真正载入、编译资产和刷新 Asset Registry 仍按 UE 要求在主线程执行，耗时取决于资产规模。

## 优先检查当前资产和可视区域（4.3.15）

资产页和场景页的 UE 发布状态检查会随点击、滚动、搜索和窗口尺寸变化更新队列，优先顺序为当前选中资产、可视区域内资产、其余筛选结果。缩略图模式和列表模式使用同一规则；筛选掉的未执行任务会移出队列，资产页继续复用已检查的缓存。每页同时只有一批检查任务，当前文件 I/O 完成后按最新顺序继续；刷新或切换项目后的旧结果仍会被丢弃，关闭窗口后不会重启检查。

## 独立 UE 制作字段（4.3.14）

资产页在【绑定状态】后、【备注】前新增【UE状态】【UE制作】。UE 状态下拉选项为【未开始】【制作中】【已完成】，写入 `asset.ue_status`；UE 制作使用与模型/绑定制作相同的分组人员列表，写入 `asset.ue_artist`。两列均支持排序，保存成功后更新当前行和列表缓存，写入失败保留原值。

模型状态移除【UE】选项，使用【未开始】【制作中】【已完成】。资产缩略图右上角 UE 角标只在 `asset.ue_status` 为【已完成】时显示；模型/绑定状态与服务器文件扫描结果不影响该角标。骨骼网格体发布成功后更新 UE 状态和 UE 制作人，保留已有模型及绑定字段、创建日期，以及未填写的中文名。历史模型状态数据不自动迁移。

各项目数据库需有 `public.asset` 的 `asset.ue_status`、`asset.ue_artist` 文本字段；缺少时可运行 `migrations/20261019_add_asset_ue_fields.sql`，已有字段和值不会被改写。此规则针对资产页，场景页继续使用 `scene.status`。

## 内容浏览器定位（4.3.13）

资产、场景页的【在内容浏览器中定位】根据当前工程中实际存在的资源启用。黄色不一致状态、本地旧版本或服务器暂时不可访问，都不影响定位。优先定位发布路径对应的本地蓝图/网格体，也支持定位材质、骨架等资源；发布路径不可用时，会查找该卡片约定的本地资产目录。定位不复制或更新资产，也不改变同步颜色。

## 加载冲突选择（4.3.8）

资产、场景、蓝图、特效、组件页加载时，如果工程中有同名但内容不同的文件，都会显示同一套冲突选择弹窗：

- 勾选要更新的文件，点击【加载选中项】，仅覆盖勾选项，其他冲突文件保留工程版本。
- 点击【全部保留并加载】，保留所有现有冲突文件，继续加载缺失文件。
- 点击【取消】或关闭弹窗，不执行本次复制。

弹窗提供文件类型、服务器大小、工程大小及路径提示，并支持全选和反选。

蓝图仍按整分类加载；特效仍包含引用的材质、贴图等依赖。两者均只覆盖勾选项。组件勾选覆盖项会先暂存，确认重启且 UE 退出后再应用；未勾选项以及工程中独有的插件文件会保留最新工程版本。全部保留时只补齐缺失文件，没有新增文件则无需重启。

## 拖放到关卡（4.3.6）

- **资产、场景**：拖入当前工程中的 Actor 蓝图、静态网格体或骨骼网格体。优先使用发布清单指定的主资产，否则自动选择可放置的本地资源。
- **蓝图**：拖入该卡片对应的 Actor 蓝图。组件蓝图、动画蓝图、控件蓝图、函数库等不能独立成为关卡 Actor。
- **特效**：拖入该卡片对应的 Niagara 系统或 Cascade 粒子系统。
- **组件**：卡片代表 UE 插件安装包，不能直接拖入关卡。加载并重启 UE 后，从内容浏览器或添加组件面板使用插件提供的资源。

黄色表示工程文件与服务器发布内容不完全一致，不影响使用本地旧版本。开始拖动时单独检查本地 `.uasset`，不会自动更新、覆盖文件或修改同步颜色。服务器暂时不可访问时，资产和场景页也会检查约定的本地 `Content/Assets/...`、`Content/Scenes/...` 目录。

本地 `.uasset` 不存在时提示先加载；资源类型不能直接放入关卡或 UE 无法加载资源时会显示相应错误。拖动卡片到关卡视口松手，由 CGToolsAssetBridge 使用 UE 原生放置逻辑处理。
